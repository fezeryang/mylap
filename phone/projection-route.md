# Surface Projection Decision

Route: **procedural materials + live semantic screen**, not photo projection.

The supplied image is a render with strongly baked neon lighting. Projecting it onto the complete
phone would preserve only this camera view, double-light the chrome/clear bumper, and turn the
screen controls into inert pixels. The user explicitly requires the UI to become genuinely
clickable, so the display is instead a dedicated interaction surface whose layout, colors, copy,
and luminous hierarchy are reconstructed as semantic HTML/CSS and mapped to the front glass.

The phone shell remains procedural PBR geometry. Visible-view palette and material response are
derived from reference crops; hidden rear/right surfaces are clearly labelled inferred. The source
image is retained exclusively as review evidence and is not shipped as an albedo shortcut.
